# Draken Consumer Contract & Sizing (DRAFT)

> Status: DRAFT. The enumerated surface opteryx + rugo consume from draken — the spec
> the rebuild is measured against, and the project sizing. Generated by grepping
> `opteryx/` + `rugo/` for `from/import draken` and `cimport ... draken` (excluding
> `draken_old`). Reminder (per `02`/`03`): the contract is **function, not signature**
> — preserve the capability, redesign the interface, update call sites.

## Size at a glance

| Metric | Count |
|--------|------:|
| Total consumption sites | **516** |

**The 369 cimport sites are the hard, gating part.** They bind `buffers.h` at compile
time, so they need the header / hand-written `extern-pxd` migration from `03` and a
**byte-frozen** struct (`00`). This dwarfs the 147 Python imports (the easy edge). rugo
is only 3 files — the weight is opteryx.

Bring-up order falls out of this: **`core.buffers` (ABI) → `vector` base + `morsel`
→ pilot type `integer64` → string, bool, float64, timestamp, array, date → the long
tail (time, decimal, null, interval, vector_vector)**, with `vector_sequence`
(ingestion) and `scalar_constructors` early since many types lean on them.

## Frozen ABI surface — `draken.core.buffers` (95 sites)

The new `buffers.h` must reproduce these **byte-identically** (the cimport contract):
- **Structs:** `DrakenVector`, `DrakenFixedBuffer`, `DrakenVarBuffer`,
  `DrakenArrayBuffer`, `DrakenStringArena`, `DrakenStringSlot`,
  `DrakenConstantStringPayload`.
- **Enum + tags:** `DrakenType`, `DRAKEN_{INT8,INT16,INT32,INT64,FLOAT32,FLOAT64,
  BOOL,DATE32,TIMESTAMP64,STRING}` (extend as types are added).
- **Inline helpers / ctors used at C level:** `str_data`, `str_length`,
  `alloc_var_buffer`, `draken_vector_from_dense` (and the `draken_identity_sel` /
  `draken_zero_sel` / `draken_zero_validity` globals from `vector_alloc.h`).

This is the only surface where "function not signature" does **not** apply — the
struct layout *is* the signature for 369 compiled sites, and it stays frozen through
bring-up.

## Dead surface (confirmed dropped)

`draken.interop.arrow` / `from_arrow` no longer appears in any consumer — the burn
removed it cleanly. `to_arrow` (export) stays. During the rebuild, anything in the old
package not in the table above is dead surface to **not** re-home.

## Open / verify
- [x] `from_scalar` — **real and core.** `scalar_constructors.from_scalar(value,
      length, dtype)`: encode a scalar literal (or `None` → all-null) into a
      **constant vector** to feed operators. Heavily used (null_reader, filter_join,
      vector_abs/math/date_part/in_list, expression evaluator). In scope, under
      `scalar_constructors`. (The lone `draken.from_scalar` grep hit was a comment, not
      an import.)
- [x] `draken.core.var_vector` — **real but internalize, and rename.** Variable-width
      buffer allocator (`alloc_var_buffer`/`free_var_buffer`/`buf_length` for
      `DrakenVarBuffer`, used by strings) — the var-width companion to `fixed_vector`.
      Only one external consumer (`vector_cast_int64_to_timestamp` hand-allocs a
      buffer), which is a smell: in the C++-first/RAII model var-buffer allocation is
      **internal**, so do **not** re-expose it — re-home that call site to a proper
      draken constructor and rename (it isn't a "vector").
- [x] `draken.morsels.align` (5) — **real, in scope.** Exposes `align_tables`,
      cimported by 5 join operators (nested-loop, asof, hashed-inner, outer, non-equi).
      It materializes a joined morsel by **taking rows from both sides by index
      arrays** — a morsel-level helper layered on per-type `take`. Belongs in the new
      core (built on the `take` op).
- [ ] Tests are excluded from this count (we deleted the arrow-dependent ones and will
      rebuild native + parity tests, `04`).

## Method (reproduce)
`grep -rn "cimport" opteryx rugo --include='*.pyx' --include='*.pxd' | grep draken`
and `grep -rnE "from draken|import draken" opteryx rugo --include='*.py'
--include='*.pyx' --include='*.pxd'`, excluding `draken_old`. Per-path tally via
`grep -rohE "draken\.[a-z_]+(\.[a-z_]+)*"` (note: `[a-z_]+` stops at digits, so
`integer64_vector` groups under `draken.vectors.integer`).
