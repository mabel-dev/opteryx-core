# READ THIS BEFORE RELYING ON A PINNED SEED
# -----------------------------------------
# A seed is an input to the GENERATOR, not a query. Reweight a join type, widen
# the joinable-category families, add a column to a fuzz table — and the same
# seed produces a different join. A pinned seed keeps a case in the corpus for
# as long as the generator is stable; it is NOT a durable regression test.
#
# The durable pin for each defect below is the matching `test_regression_*` in
# test_sql_fuzzer_join.py, which is SQL and does not drift. Same split the
# single-table fuzzer uses (seeds/single_table_select.txt).
